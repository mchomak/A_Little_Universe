# Iris Reconstruction Kit v1.3 — пошаговая инструкция

**Назначение:** офлайн-программа на Python для создания ассетов глаза из одной фотографии: контуры, ручная маска ресниц/век, ручная маска тени, две текстуры радужки, фотографический широкий план и массивы частиц для Three.js. Работает без сервера и передачи фото в интернет. **Это не генератор готовой анимированной сцены 06 и не биометрически точное восстановление скрытых участков.**

## 1. Установка в существующий репозиторий

Положите папку `iris-reconstruction-kit` в `tools/` проекта. Рекомендуемая версия Python: **3.11–3.12**, минимально **3.10**.

Из терминала в `tools/iris-reconstruction-kit`:

```powershell
python -m pip install -r requirements.txt
```

Если `python` не находится, используйте `py -3` вместо `python`. **Установка самого пакета через `pip install -e .` не нужна**: запускать можно `run_iris.py` напрямую.

Опционально на Windows можно запустить `setup_windows.bat`: он создаёт отдельную `.venv` и ставит библиотеки. Если вы уже работаете в своём Python-окружении, `.bat` не требуется.

## 2. Запуск на реальном фото

**Запускайте из корня папки с `run_iris.py`:**

```powershell
python run_iris.py "C:\Photos\eye_3_1.png" --interactive
```

HEIC тоже читается при установленном `pillow-heif`:

```powershell
python run_iris.py "C:\Photos\eye.heic" --interactive
```

Чтобы указать собственную папку экспорта:

```powershell
python run_iris.py "C:\Photos\eye.heic" --interactive --output "C:\Photos\iris_v13"
```

Если `--output` не задан, результат: `outputs/<имя_фотографии>/`. Оригинал не перезаписывается.

## 3. Что размечать вручную

Появится одно окно. Поочерёдно выполните **четыре действия**.

### Шаг A — зрачок (K — точки; P — старый круг)

1. Нажмите **`p`** (строчная латинская).
2. **Первый левый клик:** центр **чёрного зрачка**.
3. **Второй левый клик:** край **чёрного зрачка** (не внешний край цветной радужки).
4. Голубой круг должен обводить только зрачок. Чтобы переделать, снова нажмите `p` и повторите два клика.

### Шаг B — радужка (O — точки; I — старый круг)

1. Нажмите **`i`**.
2. **Первый клик:** примерный центр цветной радужки.
3. **Второй клик:** **внешний край радужки** на открытой нижней стороне, где цвет переходит в белок глаза.
4. Жёлтый круг должен совпадать с границей радужки, а не с веком или бровью. Сверху контур нужно мысленно продолжить под ресницами.

**Новый режим v1.3 — рекомендован для фотографии Василисы:**

1. Нажмите `o` (английская строчная) для внешнего контура радужки или `k` для зрачка.
2. **Первый клик — центр выбранного объекта.** После этого клика расположите **12–24 точки по границе** (можно не по порядку, но равномерно вокруг 360°). Минимум 5 точек.
3. На верхнем участке, закрытом веком, предполагаемую границу можно продолжить приблизительно по форме нижнего края. **Не проводите контур по линии века**: это не граница радужки.
4. Нажмите `c`, чтобы завершить опорный контур. Зелёная линия показывает превью замкнутой формы, жёлтая/голубая линия — сохранённый контур. `Backspace` удаляет последнюю непроверенную точку.
5. Разметьте красным все закрытые или загрязнённые ресницами участки отдельно от контура. Форма по точкам и красная маска решают **разные задачи**.

Для простой двухкликовой окружности остаются клавиши `p` и `i`. Данные из `annotation.json` версии 1.2 автоматически читаются и могут редактироваться в новой версии. Набор опорных точек сериализуется в `annotation.json`.

Выходная текстура после разметки **остаётся круглой**, как если бы глаз смотрел на камеру фронтально: приложение растягивает радиальные профили между выбранными границами. Это приближённая художественная нормализация, а не восстановление истинной трёхмерной формы радужки.

### Шаг C — закрытые участки: веко, кожа, ресницы (X)

Именно этот шаг убирает проблему, когда вместо верхней части радужки в итоговую текстуру попадает кожа!

1. Нажмите **маленькую `x`** для кисти исключения: всё закрашенное становится **красным** и не считается настоящей радужкой.
2. Закрасьте **всю кожу и верхнее веко внутри жёлтого круга**, а также крупные ресницы, закрывающие текстуру.
3. Для большого закрытого участка проще использовать **большую `X` (Shift+X)**: последовательно щёлкните вершины области (например, по нижней границе ресниц, затем вокруг верхней части). Нажмите **`c`**, чтобы залить многоугольник красным.
4. Если скрыли лишнее, **`v`** — кисть восстановления видимости. Она убирает красную маску и вновь разрешает использовать реальные пиксели.

**Важно для текущего фото:** в голубой зоне остаются тёмные нити ресниц. Их нужно точечно закрасить **красным** кистью `x` (на небольшом увеличении): `s` только осветляет, а не удаляет ресницы. При заполнении верхней половины v1.3 старается не использовать голубые области как источник.

**Не закрашивайте всю левую сторону только из-за тени.** Если фактура там различима — оставьте её как реальную, а тень выделите отдельно на шаге D.

Ключевой смысл: **красное = информации о радужке здесь нет**. Программа восстановит её художественно по видимым участкам. Если ресница пересекает радужку, можно скрыть только саму ресницу; на сложных участках допускается скрыть сектор с небольшим запасом.

### Шаг D — тень без физического перекрытия (S)

1. Нажмите **маленькую `s`**: кисть выделения **затенённых, но видимых** областей радужки. Они становятся **голубыми**.
2. На фото Василисы отметьте **тёмный левый/лево-верхний участок радужки**, где вы всё ещё видите волокна, но цвет изменился от падающей тени.
3. Не отмечайте тенью чёрный зрачок, кожу, большие ресницы или полностью потерянную фактуру. Их либо не нужно трогать, либо нужно исключить красным.
4. Чтобы убрать ошибочно отмеченную тень, нажмите **`n`** и закрасьте её.
5. Для большой затенённой области используйте **`Shift+S`** (многоугольник) и `c` для заливки.

**Тень не вычисляется автоматически по фото.** Программа исправляет только явно выделенные голубым участки. Сохраняет оттенки (не перекрашивает серо-зелёный глаз в голубой) и ограничивает усиление яркости. Сильно потерянные детали не восстановятся.

### Управление редактором

| Клавиши | Действие |
|---|---|
| **`o`, `k`** | **Опорные точки:** сначала центр, затем 12–24 точки по границе внешней радужки (`o`) или зрачка (`k`); `c` сохранить контур |
| `p`, `i` | Прежние окружности: центр → край |
| `x` | Кисть: скрыть кожу/ресницы, **красная область** |
| `v` | Кисть: вернуть ошибочно скрытый участок |
| `s` | Кисть: выделить тень, **голубая область** |
| `n` | Кисть: стереть пометку тени |
| `Shift+X`, `Shift+S` | Многоугольник для скрытого участка или тени |
| `c` | Сохранить форму по точкам (минимум 5 точек) ИЛИ закрасить многоугольник маски |
| `Backspace` | Удалить последнюю точку незаконченного контура или многоугольника |
| `[`, `]` | Уменьшить/увеличить кисть |
| `+`, `-`, колесо мыши | Увеличить/уменьшить изображение (без потери исходных пикселей) |
| Стрелки | Передвинуть просмотр при увеличении |
| `u` | Отменить последнее действие маской (не кругом) |
| `g` | Скрыть/показать подсказки поверх фотографии |
| **Enter** | Завершить разметку и запустить экспорт |
| **Esc** | Отменить без экспорта |

**Разметка сохраняется в координатах исходного изображения после обрезки**, даже если окно отображает уменьшенную фотографию или вы приближаете её колесом.

## 4. Какие результаты получатся

| Путь внутри `outputs/...` | Значение |
|---|---|
| `contact_sheet.jpg` | Общий контрольный лист: контуры, маски, радужка, широкий план, частицы |
| `annotation.json` | Геометрия и ссылки на маски для последующего повторного использования |
| `visible_mask.png` | Ручная маска: **белый = использовать**; **чёрный = скрыть** |
| `shadow_mask.png` | Теневая маска: **белый = затемнённая зона**; чёрный = остальное |
| `iris_authentic_rgba.png` | Реально видимая область радужки, после заданной коррекции тени; скрытая область прозрачная |
| **`iris_cinematic_rgba.png`** | Полный круг радужки с художественно восстановленными закрытыми секторами |
| `iris_rgba.png` | Совместимый с v1.1 псевдоним **cinematic** |
| `iris_confidence.png` | **Белый — реальные пиксели; чёрный — художественно достроенные** |
| `iris_unwrapped.png` | Исходная полярная развёртка; может включать кожу/ресницы для диагностики |
| `iris_corrected_unwrapped.png` | Полярная текстура с коррекцией отмеченных теней |
| `iris_cinematic_unwrapped.png` | Полная художественно восстановленная развёртка |
| `full_eye_original.png` | Фото всего глаза со склерой, ресницами и веками |
| **`full_eye_composite.png`** | Фотографический широкий план глаза, мягко корректирующий помеченную тень |
| **`full_eye_foreground_rgba.png`** | Фотографический **статический передний слой** век, кожи, ресниц и белка с отверстием для радужки/зрачка |
| `iris_particles.bin` | Данные точек для **cinematic** варианта |
| `iris_authentic_particles.bin` | Данные точек только по видимым реальным участкам |
| `iris_particles.npz` и `iris_authentic_particles.npz` | Массивы NumPy |
| `iris_metadata.json` | Размеры, геометрия, формат бинарных буферов, степень синтетической реконструкции |

**Критично:** `full_eye_foreground_rgba.png` — фото-слой, а не готовая 3D-модель век. Для реалистичного трекинга и моргания в Three.js нужно отдельно создать/анимировать глазное яблоко и геометрию век. Этот пакет готовит входные материалы для такого рендера. Глазная склера, ресницы и кожа **не генерируются нейросетью** и сохраняются из фото.

## 5. Повторный экспорт без повторной разметки

После первого запуска можно изменить число частиц, разрешение или силу осветления и переэкспортировать с теми же масками:

```powershell
python run_iris.py "C:\Photos\eye.heic" --annotation "outputs\eye\annotation.json" --output "outputs\eye_high" --particles 150000 --texture-size 2048 --shadow-strength 0.6
```

Чтобы **доработать** сохранённую разметку, добавьте `--interactive`:

```powershell
python run_iris.py "C:\Photos\eye.heic" --annotation "outputs\eye\annotation.json" --interactive --output "outputs\eye_v2"
```

Нужно использовать **точно то же фото и такую же обрезку**. Программа проверяет размеры, но не может гарантировать, что два разных изображения одинакового размера совпадают по кадру. Для одного лица можно сделать сколько угодно отдельных проектов.

## 6. Управление качеством

```powershell
python run_iris.py "C:\Photos\eye.heic" --interactive --angular 2048 --radial 512 --texture-size 2048 --particles 120000 --shadow-strength 0.65
```

Типичные параметры для первого запуска: 1024–2048 полярных колонок, 256–512 рядов, текстура 1024–2048, 50–120 тысяч частиц. Большие цифры не создадут настоящих деталей, которых нет на исходном фото. Их стоит увеличивать только после оценки реального iPad/Safari.

Если хотите пропустить GUI, используйте ручные окружности и маски из PNG:

```powershell
python run_iris.py "eye.png" --pupil 850 855 82 --iris 855 900 392 --occlusion-mask "visible.png" --shadow-mask "shadow.png"
```

**Числа здесь условные** и подходят только для иллюстрации формата команды; не копируйте их для другого изображения. В обоих PNG размеры должны совпадать с обработанным фото. Для `--occlusion-mask` белое означает использовать, чёрное — исключить; для `--shadow-mask` белое означает корректировать тень.

## 7. Проверка и тесты

Проверяйте в таком порядке:

1. `segmentation_overlay.png` — оба контура правильно стоят, особенно на боковых границах?
2. `annotation_preview.png` — вся кожа и отдельные тёмные ресницы внутри внешнего контура красные; видимые затенённые области голубые?
3. `iris_authentic_preview.png` — НЕ осталось кожи/ресниц в подлинной радужке?
4. `iris_cinematic_preview.png` — нет заметного шва, зеркальной симметрии, ошибочно перенесённых ресниц? v1.3 никогда не использует красные исходные пиксели при заполнении; в редких случаях возможны иные синтетические артефакты.
5. `iris_confidence.png` — восстановленные участки чёрные?
6. `full_eye_composite.png` — нет чужой кожи, двойного зрачка или грубых швов?

При неудачном восстановлении **исправьте маску, а не пытайтесь лечить артефакты свечением**. Кинематографическое заполнение основано на отражении видимой текстуры и не гарантирует качества сложного крупного плана без художественной доводки.

Тесты (дополнительные библиотеки):

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

## 8. Интеграция с сайтом

В `examples/threejs-load.ts` есть минимальный loader для `iris_particles.bin` и `iris_rgba.png`. Формат бинарного буфера не изменился: для каждой частицы **7 little-endian float32**, порядок `x,y,z,r_linear,g_linear,b_linear,size`, всего 28 байт на частицу. В Three.js нужен **один общий Canvas и текущий SceneDirector**, как в архитектуре твоего сайта.

Сам алгоритм обработает любое фото глаза, но требует ручного контроля. Это **художественная** реконструкция, а не средство идентификации или медицинского анализа. Не публикуйте в репозитории личные фото, маски и результаты без согласия владельца; `.gitignore` исключает `outputs/` и `inputs/`.

## 9. Что нового в v1.3

- `o` / `k`: многоточечные замкнутые контуры (опорные точки хранятся в source image pixels), не обязательные математические окружности/эллипсы.
- Контуры могут быть чуть асимметричны и иметь разные центры. Полярная нормализация переводит их в круглый atlas для сцены 06.
- Алгоритм восстановления исключает подмешивание **скрытых** пикселей из исходного изображения у шва. Для снижения артефактов использует только допустимые donor-пиксели и пытается избегать отмеченных тенью участков.
- Сохранена совместимость с `annotation.json` v1.2 и с форматом `iris_particles.bin`.
- Никакого автоматического распознавания ресниц в v1.3 **нет**. Сильно затемнённые, видимые или фактически перекрытые ресницы требуют кисти `x`; `s` не способна их убрать.

**Подробная рекомендация именно для твоего снимка:** точечный контур внешней радужки ≈ 14–20 точек, зрачок можно оставить окружностью `p` или разметить `k` (8–12 точек), затем маленькой красной кистью убрать тёмные ресницы, нависающие над верхним/левым сектором радужки. Для фотометрической коррекции отдельно отметь голубым только участки, где видны собственные радиальные волокна.

## Локальные эксперименты с ручной разметкой

Персональные изображения и результаты по умолчанию исключены из Git (`experiments/`).
Рабочий набор этой фотографии: `../images/eye_3_1.png` и неизменяемая копия
`experiments/annotation_backup/annotation.json` с соседними масками. Перед запуском
проверяйте соответствие фотографии и разметки. Runner сохраняет SHA-256 фото,
разметки и файлов кода, состояние Git, версии библиотек, параметры, seed и журнал;
исходную фотографию он не копирует. Каждая команда создаёт новую нумерованную
папку, существующий результат не перезаписывается:

```powershell
python run_experiment.py --run-label my_test --mode illumination --seed 42
python run_experiment.py --run-label my_test_damage --mode damage --seed 42
python run_experiment.py --run-label my_test_blend --mode blend --seed 42
python run_experiment.py --run-label my_test_selective --mode selective --seed 42
python compare_experiments.py
```

`illumination` оценивает плавную освещённость по радиальным строкам; `damage`
добавляет экспериментальную маску тёмных дефектов; `blend` дополнительно применяет
экспериментальный выбор чистых доноров. Последний режим не гарантирует плавный шов:
оцените его визуально. Ручные маски не изменяются. Обычный CLI по умолчанию сохраняет
поведение `legacy`; режим выбирается также через `--reconstruction-mode`.
Экспериментальная карта уверенности: 255 исходный пиксель, 192 фотометрическая
коррекция, 96 локальная синтетическая замена, 0 синтез закрытой области. Значения
в квадратной карте интерполируются, поэтому на границах возможны промежуточные.
Метрики являются диагностическими и не подтверждают реальный рисунок скрытой радужки.
Скрипт сравнения обновляет только общие производные таблицы и контактные листы;
выходы отдельных запусков не заменяются. Повторение требует той же версии кода:
SHA-256 в metadata идентифицирует её, но не является архивом исходников.
