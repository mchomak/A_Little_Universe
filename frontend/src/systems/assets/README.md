# Runtime preparation

`AssetManager({ loadModules, development?, manifest?, fetch?, verifyOffline? })` exposes `prepare(onProgress?)` and `retry(onProgress?)`. Both resolve a `PreparationResult`: `ready`, `offline` (`verified`, `unavailable`, `development`), `errors`, `warnings`. A mandatory resource error blocks readiness; optional errors become warnings. Retries preserve validated resources and repeat unfinished requests and cache verification. Progress counts only successfully prepared mandatory units; unmeasurable module/cache operations have named stages.

`RuntimeManifest` has a version and assets with `url`, `kind` (`image`, `audio`, `model`, `file`), `required`, optional `bytes`, `sha256`, `contentType`. Images decode and release their bitmap; audio decodes through OfflineAudioContext without unlocking playback. Configured glTF/GLB assets dynamically import GLTFLoader and perform actual parsing, buffer/accessor/geometry/material/texture preparation. Prepared temporary geometry, materials, textures and image bitmaps are disposed afterwards. External model dependencies must also be included in the runtime manifest for offline use. Film rendering remains responsible for allocating GPU objects; this service does not claim a GPU warmup or an unavailable tracking model.

The Vite plugin generates `runtime-manifest.json` and `sw.js` from emitted production files. Add runtime files through Vite imports so they are included; reference keyframes outside frontend are not shipped. Current scenes use code-generated geometry and system fonts; no photo/audio/model assets are invented. The build version includes resource hashes and the cache implementation, so changes to offline behavior also invalidate the version.

The worker caches only exact current-build URLs, index and manifest. It does not handle API, camera, recording or upload requests. Both installation and page verification read every mandatory response and check byte length and SHA-256. `ignoreVary` is limited to immutable same-origin resources: Vite preview's `Vary: Origin` must not prevent CORS module requests from matching installation fetches. Navigation and manifest use network first and an internally consistent offline snapshot as fallback.

Existing film tabs are not forced onto an updated worker. A waiting replacement produces an explicit offline limitation until old tabs close. A matching active worker and verified cache need no network update request on offline reload. Browser storage can still be evicted later; verification describes the current cache, never permanent storage.

`Bootstrap` mounts `Preloader` before dynamically importing the App/Three graph. The static HTML supplies an initial message if JavaScript is slow. `Preloader({manager,onReady})` can be reused for development reruns, paints before the heavy import, then collapses the particles and waits 1.25 seconds after successful preparation. Storage failure offers retry or explicit continuation with a clear offline-reload limitation. Failed module imports also offer reload because browser module maps can preserve import failures. No media permissions are requested here.
