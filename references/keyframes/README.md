# Ключевые кадры

Это материалы художественной разработки, **не runtime-ассеты**. Пользователь добавляет изображения самостоятельно. Сейчас изображений нет; Codex не генерирует их в рамках инициализации.

Источник shot IDs: [Storyboard v1.1](../../A_Little_Universe_for_Vasilisa_Storyboard_v1.1.md). Сценарий не дублируем и не переименовываем.

## Организация

```text
references/keyframes/
  README.md
  S03_lily_open/
    originals/       неизменённые исходники, включая исходные названия
    draft/           рабочие версии для обсуждения
    approved/        только явно утверждённые версии
    index.md         связь файлов с кадрами сценария и статусом
```

Папки сцен создавать по мере появления изображений: `S01_prologue`, `S02_lily_growth`, `S03_lily_open`, `S04_name_portrait`, `S05_memories`, `S06_eye`, `S07_galaxy_bouquet`, `S08_greeting`, `S09_ending`. Для технических стадий — `S00_preload`, `S00_1_permissions`.

## Нейминг

`S03_SH04_lily_open_v01.png` — сцена 03, кадр 03.4, краткое описание, версия 01. Для альтернатив: `S03_SH04_lily_open_variant-b_v02.png`. Состояние задаётся папкой `draft/approved`, не словом «final» в имени. Использовать латиницу, подчёркивания, ведущие нули и расширение реального формата.

Дробный технический номер 00.1 кодировать как `S00_1_SH01_permissions_v01.png` и явно сопоставлять в index. Если понадобится несколько изображений одного кадра — добавить `a/b` после SH (`SH04a`), сохранив связь с 03.4.

## Правила сохранности и утверждения

1. Сохранять оригиналы неизменными в `originals/`. Не перезаписывать и не сжимать единственную копию. При нормализации имени сохранить исходное имя в index.
2. Новые варианты/правки — новый номер версии в `draft/`. Не затирать предыдущие.
3. Копировать выбранный вариант в `approved/` только после явного утверждения пользователя; сохранить draft и оригинал. Само наличие файла в папке не заменяет запись решения в index.
4. Не заменять утверждённый кадр молча: новая версия, новое утверждение; предыдущую отметить как superseded, сохранив файл.
5. Каждый файл сопоставлять с точным заголовком/номером кадра сценария. Отметить какие именно свойства утверждены: композиция, палитра, форма, свет, типографика, движение камеры. Статичный референс сам по себе не является готовым 3D-объектом.
6. Не включать references целиком в production. Будущие модели/текстуры/фото переносить отдельно в `frontend/src/assets/` или `frontend/public/assets/` после выбора, оптимизации и проверки прав/приватности. Приватные фото не публиковать вместе с публичным репозиторием без решения владельца.
