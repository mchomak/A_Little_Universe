# Спецификация: фото-частицы и проявление коллажей

## Задача

При фокусе на картину зритель должен увидеть связанные фотографии как собранные из света снимки, а не как прямоугольники, которые просто проявились. Затем снимки должны разрешиться в обычные фотографии. При выходе из фокуса они должны мягко исчезнуть, не создавая вторую тяжёлую систему частиц для всей галереи.

## Решение

Основная картина сохраняет существующую рамку и механику фокуса. Пока точка галереи не выбрана, её дополнительные фото не смонтированы. У выбранной точки они занимают текущие боковые слоты и сначала собираются в цветные облака частиц, затем под ними постепенно становится чётким исходное изображение. После завершения остаются обычные фотографии.

Эффект строится внутри существующей сцены и WebGL-рендера. Шейдер читает UV, цвет и яркость уже загруженной текстуры фото; отдельные Canvas, renderer, WebGL context, сервер или зависимость не добавляются. По мотивам `memory-signal-threejs` применяются распределённые по изображению точки, мягкое additive-свечение, небольшой шум и рельеф по глубине. Исходники внешнего репозитория не копируются.

## Поведение и тайминг

1. Фото основного события, его фокус, камера, рама и свет продолжают работать существующим способом. Список дополнительных изображений создаётся только для выбранной картины.
2. Каждый дополнительный слот получает детерминированную UV-точку на поверхности фото и детерминированное смещение старта. Частица читает цвет изображения из texture sampler. Яркость задаёт её видимость и мягкий размерный акцент; additive point sprite даёт мягкий край. Шум и z-relief затухают по мере сборки.
3. Для фото со слотом 2, 3 или 4 начало сдвинуто на `slotOrder * staggerDelay`, чтобы пропуск отсутствующей позиции не менял геометрию слотов. Начало показа — слабые рассеянные точки; далее они собираются на прямоугольнике. Scatter и шум ограничены bounds собственного фотослота и не пересекают главную картину или проход.
4. После `assembleDuration` нормальное фото начинает проявляться через собственный shader opacity. Его детали разрешаются из крупных ячеек в точные UV выборки по приёму progressive photo recovery из прежнего `IdentityScene`; частицы в это время теряют opacity. По завершении виден исходный снимок.
5. При unfocus timeline уменьшается обратно. Если focus быстро вернулся или сменился, направление разворачивается с текущего значения. Контроллер галереи сохраняет выбранную картину до окончания выхода; после снятия focus React размонтирует компоненты.
6. При `reducedMotion` используется тихое проявление фото с минимальным/нулевым движением и без активного particle scatter. Ошибка загрузки использует текущую fallback-текстуру; незаданные URL и пустые слоты не создают мешей.
7. При выключенном particle-режиме дополнительное фото всё равно мягко проявляется, без particle pass. Коллажи с одним дополнительным фото используют ту же реализацию ради визуальной согласованности (A01 → R01). Основная проверка — события с 2–3 дополнительными фотографиями.

## Решения по реализации

- Геометрия содержит ограниченный детерминированный UV-набор и смещения; геометрия и материалы создаются только у сфокусированного события, не меняют React state каждый кадр, освобождаются при cleanup.
- Один загруженный `Texture` подключён одновременно к плоскости обычного фото и материалу точек. Настройки обновляют uniforms; изменение плотности пересобирает только выбранную геометрию и освобождает предыдущую.
- Восемь DEV-параметров по умолчанию: 640 точек на фото, 2.6 px, noise 0.035, z-depth 0.42 м, glow 1.0×, assembly 0.72 с, photo reveal 0.68 с, stagger 0.14 с. Нормализация ограничивает плотность до 96–2400 на фото, размер до 1–8 px, шум 0–0.12, глубину 0–0.8 м, свечение 0–2×, сборку 0.25–2 с, проявление 0.25–2 с, stagger 0–0.5 с.
- Персональное отключение задаётся небольшим объектом параметров `galleryCollageConfig`, ключ — неизменный event id; подписи и порядок событий в этот механизм не вмешиваются.
- DEV-контролы находятся в свёрнутой группе «Частицы дополнительных фото»; конфигурация обновляет уже существующий Scene Composer.
- Активный Scene 04 использует `LilyDissolveParticles`: исходную поверхность, image-derived target attributes, мягкое перемещение и рассеяние частиц в shader. Этот source → target → dissolve цикл адаптируется для UV-точек фотографии без lily mesh. В активном пути нет финального crossfade к нормальному фото; прежний `IdentityScene` содержит progressive recovery/photo-cell shader. Его photo-resolution процедура выносится в общий helper и адаптируется для коллажей, сохраняя прежнюю последовательность. Активный Scene 04 не меняется.
- Производительность проверяется при 0, 1 и 3 дополнительных фото и после повторных focus/unfocus циклов. Активны не более трёх Points-систем выбранного события; после unmount геометрии, материалы и загруженные textures освобождены, renderer.info возвращается к baseline с учётом штатного cache Three.js.
- Перед локальной приёмкой ранее работавший dev server останавливается и перезапускается на актуальной ветке; финальная ссылка указывает на этот экземпляр.
- Все тайминги привязаны к focus-изменению и Three frame delta. Глобальные film timing, CameraDirector, persistent canvas и проход галереи не меняются.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `gallery/collage` | layout дополнительных слотов, детерминированная UV/particle geometry и функции timeline | тип фото, layout, geometry builder, timeline progress | генерацию seed, ограничение input, slot timing |
| `shared/progressivePhotoReveal` | cell-resolution sampling и interpolated photo alpha | shader snippet/fragment helper, progress utility | per-pixel детали и базовую smoothstep математику |
| `GalleryScene` | загрузку выбранных texture, shader uniforms, render и lifecycle эффекта | внутренний `CollageExtraPhoto` | шейдеры, общие textures, cleanup и focus synchronization |
| `galleryCollageConfig` | параметры конкретных событий по event id | readonly lookup `getGalleryCollageConfig(eventId)` | пустые значения и default включённого режима |
| `SceneComposerConfig` / DEV | диапазоны и значения по умолчанию | `scenes.gallery.collage*` settings | merge, migration defaults и безопасная нормализация |

Шов тестирования: `gallery/collage` — deterministic geometry, slot-aware timeline, missing-slot behavior и обратимость; существующие Scene Composer tests проверяют defaults, clamping, reset и импорт/экспорт. Компонент проверяется интеграционно в одном browser renderer.

## Вне рамок

- Копирование `memory-signal-threejs` целиком, отдельное приложение, новая зависимость, canvas или renderer — запрещено R11/R24.
- Замена layout, основного фото, камеры, освещения, фокуса и перехода галереи — вне R23.
- Дополнительные подписи к фото 2–4 не добавляются; пользователь просит только визуальный коллаж.
- Merge в `main` не выполняется согласно R50.

## Открытые места

Нет. Фото остаются локальными runtime assets галереи; для временно отсутствующего снимка применяется уже существующая fallback-текстура, не выдумываются пользовательские фотографии или подписи.

## Добавления и допущения

- **A01 → R01:** единая photo-particle анимация применяется также, если у события только одно дополнительное фото, чтобы сохранить текущую механику при малом числе снимков.
- `reducedMotion`, texture fallback, пропуск отсутствующих файлов, безопасные границы DEV-полей и освобождение GPU-ресурсов — требования проекта и технические решения, не новые пользовательские возможности.
- Для R28 scatter ограничен bounds каждого дополнительного фотослота.
- Общий helper содержит photo-cell refinement и применяется как в галерее, так и в старом restore shader. Активная сцена 04 не получает нового слоя проявления.
