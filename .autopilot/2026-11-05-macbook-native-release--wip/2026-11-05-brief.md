\# A Little Universe for You — macOS App + Automatic Local Recording\
\
\## Цель\
\
Превратить существующий Three.js/WebGL-сайт в автономное macOS-приложение для MacBook Apple Silicon M2.\
\
Приложение должно запускаться двойным щелчком, открывать фильм на весь экран и автоматически запускать локальную запись камеры, микрофона и экрана после информированного подтверждения зрителя.\
\
\*\*Никакого выбора между режимами записи и просмотра.\*\* Предусмотрен один сценарий запуска.\
\
\## 1. Git\
\
\- Создай НОВЫЙ worktree от актуального \`main\`.\
\- Ветка: \`codex/macbook-native-release\`.\
\- Не используй старые экспериментальные ветки.\
\- Не изменяй сцены, анимации, GLB, шейдеры и DEV-пресеты без необходимости.\
\- Не выполняй merge в \`main\`.\
\
\## 2. Автономное macOS-приложение\
\
Предпочтительно использовать Electron.\
\
Создай \`A Little Universe for You.app\` для macOS ARM64.\
\
Требования:\
\
\- Запуск двойным щелчком.\
\- Полноэкранное окно без браузерного интерфейса.\
\- Все ассеты включены в приложение.\
\- Полная работа без интернета.\
\- Не требуется установленный Node.js или ручной запуск сервера.\
\- Сохранена DEV-панель.\
\- Поддерживается повторное открытие и просмотр фильма.\
\- WebGL2, Three.js, GLSL, GSAP и загрузка моделей работают без изменений.\
\
\## 3. Запуск записи\
\
При открытии приложения показывай один простой стартовый экран с понятным уведомлением о записи камеры, микрофона и экрана.\
\
После явного подтверждения запуска фильм и запись начинаются автоматически.\
\
Не добавляй отдельный переключатель режима записи. Не запускай захват до подтверждения.\
\
На моём MacBook я заранее предоставлю приложению необходимые системные разрешения. Используй штатные API macOS и корректные настройки \`Info.plist\`, не пытайся обходить защиту системы.\
\
Если разрешения отсутствуют, покажи понятное сообщение о необходимых действиях.\
\
\## 4. Независимые потоки записи\
\
Организуй три потока:\
\
1\. \*\*Camera\*\* — запись реакции с веб-камеры MacBook.\
2\. \*\*Microphone\*\* — отдельная запись микрофона.\
3\. \*\*Screen\*\* — запись фильма в окне приложения.\
\
Все потоки используют согласованные временные метки.\
\
Запись не должна зависеть от таймлайна фильма:\
\
\- Смена сцен её не останавливает.\
\- Конец титров её не останавливает.\
\- Повторный просмотр её не останавливает.\
\- Галактика может вращаться бесконечно, запись продолжается.\
\
Для владельца добавь в DEV-панель раздел \`Recording\` с кнопкой \`Stop & Save\`. Также обеспечь доступную зрителю возможность остановить запись.\
\
\## 5. Надёжное локальное сохранение\
\
\*\*Нельзя накапливать всю запись в оперативной памяти до её завершения.\*\*\
\
Сохраняй самостоятельно воспроизводимые сегменты приблизительно по 60 секунд, с более частой фиксацией промежуточных данных по возможности.\
\
Структура:\
\
\`\`\`text\
Movies/A_Little_Universe_Records/\
&#x20; session_YYYY-MM-DD_HH-MM-SS/\
&#x20;   camera/\
&#x20;     segment_0001.webm\
&#x20;   microphone/\
&#x20;     segment_0001.webm\
&#x20;   screen/\
&#x20;     segment_0001.webm\
&#x20;   final/\
&#x20;     camera_full.mp4\
&#x20;     microphone_full.m4a\
&#x20;     screen_full.mp4\
&#x20;     combined.mp4\
&#x20;   manifest.json\
&#x20;   recording.log\
\`\`\`\
\
Используй реально поддерживаемые форматы.\
\
Требования:\
\
\- Никаких сетевых запросов для хранения.\
\- Каждая сессия сохраняется в отдельной папке.\
\- Не перезаписывать старые записи.\
\- Фиксировать время начала, длительность и ошибки сегментов.\
\- Не удалять корректно сохранённые фрагменты при сбое.\
\- Предусмотреть восстановление записи после аварийного завершения.\
\- Проверить реальную воспроизводимость каждого сегмента.\
\
\## 6. Завершение и объединение\
\
После остановки:\
\
1\. Закрыть активные потоки.\
2\. Сохранить последние фрагменты.\
3\. Проверить целостность файлов.\
4\. Собрать цельные записи камеры, микрофона и экрана.\
5\. По возможности создать синхронизированное итоговое видео.\
6\. Сохранить оригинальные сегменты.\
\
При необходимости используй поставляемый вместе с приложением FFmpeg или другой надёжный инструмент.\
\
Не выполняй простую бинарную конкатенацию видеофайлов.\
\
Если объединение завершилось ошибкой, исходные сегменты остаются доступными для последующего восстановления.\
\
\## 7. Производительность\
\
Главный приоритет — плавная работа фильма.\
\
Начальные ориентиры:\
\
\- Camera: 720p.\
\- Screen: до 1080p.\
\- Частота кадров и битрейт — с учётом реальной производительности.\
\- Минимальное влияние записи на WebGL.\
\
Ошибки записи не должны приводить к зависанию фильма.\
\
Если отдельный источник записи недоступен, сохраняй уже разрешённые потоки и сообщай об ошибке.\
\
\## 8. DEV-панель\
\
Добавь раздел \`Recording\`:\
\
\- Статус записи.\
\- Состояние камеры, микрофона и экрана.\
\- Продолжительность.\
\- Количество сохранённых сегментов.\
\- Папка сохранения.\
\- Свободное место.\
\- Список ошибок.\
\- \`Stop & Save\`.\
\- \`Open Recording Folder\`.\
\
Не меняй существующие настройки других сцен.\
\
\## 9. Тестирование\
\
Проверь:\
\
\- Production build.\
\- Сборку \`.app\` под ARM64.\
\- Автономную загрузку всех ассетов.\
\- Полноэкранный запуск.\
\- Разрешения macOS.\
\- Запись всех трёх потоков.\
\- Продолжение записи после окончания титров.\
\- Сохранение сегментов.\
\- Остановку и сборку итогового видео.\
\- Восстановление после имитации сбоя.\
\- Повторный запуск приложения.\
\- Отсутствие регрессий в WebGL-сценах.\
\
Если у тебя нет доступа к реальной macOS, подготовь автоматизированные тесты, но явно отдели их от проверки на физическом MacBook.\
\
\## 10. Порядок реализации\
\
Раздели разработку на три этапа:\
\
\*\*Этап A:\*\* автономное macOS-приложение, запускаемое двойным щелчком.\
\
\*\*Этап B:\*\* захват камеры, микрофона и экрана с локальным сохранением независимых сегментов.\
\
\*\*Этап C:\*\* объединение записей, восстановление после сбоя, обработка ошибок и итоговые проверки.\
\
Каждый этап заверши отдельным коммитом.\
\
\## 11. Git и отчёт\
\
\- Продолжай только в \`codex/macbook-native-release\`.\
\- Выполни \`npm run check\` и необходимые тесты Electron.\
\- Создай коммиты и push в feature-ветку.\
\- Не выполняй merge в \`main\`.\
\
В отчёте укажи:\
\
1\. Как запускается приложение.\
2\. Какие разрешения нужно заранее предоставить.\
3\. Как запускается и останавливается запись.\
4\. Где сохраняются сегменты.\
5\. Как создаётся итоговое видео.\
6\. Как восстанавливаются данные после сбоя.\
7\. Какие проверки реально выполнены.\
8\. Что осталось проверить на физическом MacBook.\
9\. Как безопасно интегрировать изменения в \`main\`.\
\
\*\*Главная цель:\*\* удобный запуск локального фильма и максимально надёжная непрерывная запись после подтверждения, с сохранением данных даже при сбоях приложения или отсутствии интернета.
