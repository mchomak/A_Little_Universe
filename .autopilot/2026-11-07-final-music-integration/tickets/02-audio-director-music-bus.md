# 02 — Общая музыкальная шина AudioDirector

**Требования:** R12–R16, R18, R20
**Blocked by:** —
**Зона:** `frontend/src/systems/audio/`
**Волна:** 1
**Status:** ready

## Что должно заработать

Существующий app-lifetime `AudioDirector` обслуживает cues и музыку одним ленивым `AudioContext`. Музыка получает отдельный master и каналы двух HTML media elements. Существующий stop cues не завершает партитуру; источники можно безопасно подключать и освобождать без дубликатов.

## Из брифа, дословно

> «Если уже есть подходящий AudioManager, расширь его.»
> «Не создавать отдельный AudioContext для каждой сцены.»
> «Избегать одновременного случайного воспроизведения нескольких экземпляров одного трека.»
> «Освобождать неиспользуемые аудиоресурсы.»

## Разделы спецификации

Решения 1–2; граница `AudioDirector`.

## Критерии приёмки

- [ ] Найденный app-level AudioDirector остаётся единственным владельцем AudioContext; его существующие SFX и unlock semantics сохранены.
- [ ] Добавлен отдельный music master с изменяемой громкостью, pause/resume и dispose; `stop()` SFX не останавливает музыку.
- [ ] `createMusicChannel(element)` возвращает `MusicChannel = { gain: GainNode; dispose(): void }` после unlock и `null` до unlock; MusicDirector сможет планировать equal-power automation напрямую через `gain.gain`.
- [ ] Медиа-источник, подключённый к музыке, переиспользуется идемпотентно; отключение освобождает только относящийся к нему узел.
- [ ] Создание двух каналов для слотов использует одну и ту же шину/контекст; повторное подключение не создаёт звучащие дубликаты.
- [ ] Unit tests проверяют общее владение контекстом, разделение уровней SFX/music и очистку channel nodes.

## Ограничения

Не создавать новый контекст на сцену или трек, не менять scenes, timing и существующие звуковые cues.
