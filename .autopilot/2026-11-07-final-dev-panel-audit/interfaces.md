# Границы, зафиксированные спецификацией

## Архитектурные границы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| DEV Scene Editor, Timeline и видимые Review Notes | Представлением контролов, русскими метками и раскрытием текущей сцены | Текущие UI actions и typed config updates | Конфигурационными defaults и сериализацией |
| Модель пресета | Версиями формата, проверкой scope/значений и созданием scope patch | `captureScenePreset`; `parseScenePreset(value, expectedScope?, normalizeConfig?)`; `scenePresetPatch` | Случайной заменой всего config, UI деталей и runtime-импортом конфигурации |
| Хранилище пресетов | Локальной записью отдельно по scope и package seeds | list/read/save; `save(value, expectedScope?)` для выбранного scope | Конфигурацией фильма и runtime-ресурсами |
| Scene Composer store | Нормализованной текущей config v26 | Существующим scoped patch/update API | DEV состоянием, выбранным пресетом и DOM-развёрткой |
| Тестовый шов | Чистыми моделями/хранилищем и store-патчем | Unit tests с временным storage | Настоящими пользовательскими preset-файлами |

Текущая схема `SceneComposerConfig` — v26. Файл отдельного пресета остаётся `formatVersion: 1`, scope ID и внутренние ключи не переименовываются. Парсер принимает известные версии схемы 1–26, отклоняет неподдерживаемую будущую версию и неизвестные/некорректные scope до применения. Модель принимает optional `normalizeConfig` callback: модель и Vite plugin остаются без runtime-зависимости от config/font assets, а browser API передаёт существующий `normalizeConfig` для проверки известных полей и допустимых диапазонов. Импорт пресета патчит только `scenes.<scope>`; старое поле `openingBackground` разрешено прочитать для совместимости, но не применять через импорт сцены. Новые per-scene capture исключают общий кадр фона. Отсутствующие свойства старого JSON сохраняют текущие значения; вложенные данные клонируются и сливаются глубоко, затем конфигурация нормализуется до единственного обновления store.

Browser API при сохранении передаёт выбранный UI scope отдельно от JSON; `save(value)` остаётся совместимым и использует scope документа, если expected scope не передан. UI import всегда сверяет JSON с текущим scope.

Параметры семечка и роста лилии принадлежат существующему scope `growth` (сцена 02), остаются разными группами UI. `bloom` (03), `identity` (04), `gallery` (05) и `cosmos`/`galaxy` используют существующие scope. У greeting нет config-полей и preset scope; не создавать новые контролы/тайминги, меняющие анимацию. `growthCloudLayerControls()` отображается единожды в секции роста и помечается общей настройкой сцен 02–03. Общие параметры качества, скорости, DPR и кадрирования фона остаются в отдельной секции «Общие настройки».

## Стек и проверки

- React, TypeScript, Vite, Three.js, React Three Fiber, GSAP; новых зависимостей не добавлять.
- Команды из `frontend`: `npm run check`, связанные тесты через `npm run test -- ...` (уточнить доступный script в `package.json`), production `npm run build`.
- Не менять GLB, фото, художественные defaults, материалы, свет, анимации, маршрут фильма, runtime/renderer/camera, запись, macOS/Electron-обёртку или реальные preset-файлы.
- DEV-пресеты используют file-backed API в Vite/preview и per-scope localStorage в packaged Electron; не менять механизм хранения и seed-значения.
- Тесты используют in-memory/временное хранилище и fixtures, никогда не записывают `frontend/scene-presets/`.
- Исходная ветка — `main`. Перед запуском проверены `git status` и отсутствие активной параллельной работы; сохранять все исходные пользовательские изменения и не включать их в коммиты.
- Если отсутствует обязательная зависимость/среда, вернуть `BLOCKED`, не устанавливать пакет без необходимости.

## Владение по задачам

- T01: модель отдельного пресета и её тесты; scoped capture/parse/patch, совместимость и защита от импорта за пределы сцены.
- T02: UI-контролы импорта/экспорта JSON отдельного пресета; вызывает модель T01 и текущий store API.
- T03: DEV-панель, группировка и раскрытие секций, подписи/подсказки/сообщения/timeline на русском; не меняет serialized keys.
- T04: проверка и атомарность полного Scene Composer JSON импорта; все проверки выполняются до единственного изменения store.
