## Что должно заработать

Существующая схема отдельных пресетов сохраняется, а capture/import затрагивают только конфигурацию выбранного scope. Старые пользовательские JSON остаются читаемыми без потери известных значений, некорректный или будущий формат отклоняется до изменения состояния. Другие сцены, общие настройки, runtime, камера и renderer при импорте не меняются.

## Из брифа, дословно

> «Нельзя сбрасывать другие сцены при загрузке одного пресета.»
> «Нельзя подменять глобальный объект настроек целиком ради импорта одного раздела.»
> «Не допускать потери настроек из-за shallow merge вложенных объектов.»

## Критерии приёмки

- [x] Поддерживаемая `ScenePresetV1` остаётся `formatVersion: 1`; версии composer 1–26 валидируются, будущая неподдерживаемая схема и неправильный scope безопасно отклоняются.
- [x] `parseScenePreset` принимает optional callback нормализатора и проверяет типы/диапазоны известных ключей только при его передаче; production model остаётся type-only зависимостью от config, чтобы Vite config не загружал CSS/font assets.
- [x] Capture содержит только настройки своего `scenes.<scope>`; совместимое старое `openingBackground` можно прочитать, но scoped import не применяет его.
- [x] Apply создаёт независимый deep clone, сохраняет отсутствующие поля текущими значениями и патчит только свой scope без замены корневой config.
- [x] Тест A≠B подтверждает, что импорт одного scope не меняет соседнюю сцену, общие настройки и вложенные ссылки; round-trip/capture покрывает все актуальные preset scopes и внутренние ID.
- [x] Тесты старого формата и некорректных типов/диапазонов с текущим normalizer доказывают отказ без частичного применения; реальные preset-файлы не используются как тестовый storage.
- [x] Изменены только файлы своей зоны; художественные defaults и пользовательские preset JSON сохранены.
