## Что должно заработать

В каждой поддерживаемой сцене можно экспортировать JSON только её текущего пресета и импортировать файл обратно. Импорт требует совпадения scope и применяет только этот scope через модель T01; пользователь получает понятное сообщение об ошибочном файле, а конфигурация остаётся целой.

## Из брифа, дословно

> «Экспортировать пресет сцены 02.»
> «Импортировать ранее экспортированный пресет сцены 02.»
> «Проверить, что параметры сцены 04, галереи и общие настройки не изменились.»

## Разделы спецификации

§2: round-trip каждого поддерживаемого scope, изоляция импорта, проверка scope; технические решения §§30–36.

## Критерии приёмки

- [x] Экспорт сериализует валидный JSON v1 только выбранного preset scope; импорт читает JSON, валидирует scope/версию и вызывает scoped apply T01.
- [x] UI/API передают существующий `normalizeConfig` в T01; импорт, чтение и пользовательское сохранение отклоняют известные значения неверного типа/диапазона до изменения config, не импортируя normalizer из Vite plugin/server.
- [x] UI передаёт expected scope отдельно при сохранении, packaged storage отклоняет документ, scope которого не совпадает с выбранным, а совместимый вызов без expected scope использует документный scope.
- [x] Round-trip через UI подтверждён для `preload`, `prologue`, `growth`, `bloom`, `identity`, `gallery`, `galaxy`; импорт одного scope не меняет другие сцены или общие параметры.
- [x] Подписи, подсказки, ошибки/подтверждения, кнопки импорта и экспорта в контролах пресета переведены на русский; несовпадающий scope, повреждённый JSON и неверная схема дают понятное сообщение и не меняют config.
- [x] Внутренние scope IDs и поля сериализации остаются без изменений; тесты работают с временными данными, существующие пользовательские файлы не трогаются.
