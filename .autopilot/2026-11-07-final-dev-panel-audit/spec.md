# Спецификация: аудит DEV-панели и пресетов

## Задача

DEV Scene Editor вырос вместе с фильмом: сейчас настройки разных сцен доступны через общую панель, а пресеты должны оставаться удобными и безопасными при смене конфигурации. Итог — оператор быстро находит русские настройки именно выбранной сцены, может сохранить и переносить только её конфигурацию, а фильм одинаково работает с открытой и закрытой DEV-панелью.

## Решение

Сохранить текущие React/TypeScript/Scene Composer и формат пользовательских пресетов. Привести отображаемые подписи в актуальных разделах панели к русскому, сохраняя внутренние идентификаторы и структуру конфигурации. Проверить фактические активные сцены и сгруппировать доступные контролы по сцене; app-wide параметры показывать отдельно. Не менять художественные defaults, фильм-маршрут и runtime.

Импорт сначала полностью разбирает, проверяет и мигрирует документ во временное значение. Только после успешной валидации он формирует патч ограниченной области. Применение патча сохраняет корневую конфигурацию и остальные сцены, делает независимую копию данных и объединяет вложенные объекты без потери отсутствующих полей. Для R31 все fallible checks, включая локальную загрузку шрифта при полном JSON, завершаются до единственного updateConfig; ошибка до применения ничего не меняет.

## Технические решения

- Решения этой секции конкретизируют R13–R18, R20–R34 и R39: исходный код использует `SceneComposerConfig` schema v26. README/AGENTS и `docs/architecture.md` содержат устаревшие сведения о v24/v11. Существующие config IDs не переименовываются и художественные defaults не меняются.
- Текущий формат файла отдельного пресета остаётся `formatVersion: 1`, `configSchemaVersion` сохраняет номер схемы снимка, а существующие scope IDs и поле `scene` сохраняются. Парсер принимает текущую и поддерживаемые старые schema версии 1–26, но отклоняет будущую неподдерживаемую версию; ни один неизвестный документ не применяется частично.
- Для изоляции R20–R30 scope сверяется с ожидаемым разделом UI. Пресет импортирует только соответствующие настройки `scenes.<scope>`. `scenes.openingBackground` — общее кадрирование фона, которое сейчас присутствует в старых opening-пресетах; его выводят из новых per-scene capture и применяют только отдельным полем Общих настроек. Старое поле `openingBackground` остаётся допустимым при чтении, но не применяется импортом пресета сцены, чтобы сохранить изоляцию. Другие сцены, renderer, камера, runtime, состояния проигрывателя и DOM timeline не меняются.
- Для структуры R01–R10 и независимости R20–R30 параметры семечка и роста лилии в текущей модели принадлежат одному scope `growth` и одному film route `growth` (scene 02). Внутри этого раздела они остаются разными вложенными группами «Семечко» и «Рост лилии»; film route и preset scope `growth` соответствуют текущей сцене 02, поэтому scene preset покрывает именно конфигурацию этого маршрута; новые config keys или scopes не нужны. Сцена `bloom` (03), портрет `identity` (04), галерея (05) и `cosmos`/`galaxy` остаются самостоятельными по текущим ID. У greeting нет config-параметров и preset scope; тайминги, тексты и анимация остаются существующими константами, новые контроли не вводятся из-за запрета менять анимации.
- Для R04/R10 `growthCloudLayerControls()` относится к `scenes.growth` и больше не дублируется в `bloom`; подпись явно сообщает, что эта конфигурация общая для сцен 02–03, и контрол остаётся в одном месте владельца.
- Для R28/R31/R34 подготовка импорта создаёт полную независимую копию scope и глубоко накладывает только разрешённый снимок на текущее значение того же scope. Отсутствующие в старом JSON свойства оставляют текущее значение. Сериализуемая модель пресета не делает runtime-import `config.ts`: Vite config загружает её в Node через `dev-scene-preset-store`, а `config.ts` тянет `fonts.css` и font asset `?url`. Модель принимает необязательный callback существующего normalizer; UI/API при чтении и импорте передают `normalizeConfig`, которая проверяет известные типы и диапазоны до применения. Серверный Vite plugin продолжает проверять envelope/scope без загрузки browser assets. Результат готовится до единственного вызова store.
- Для R12/R16/R20/R21 добавить отсутствующие per-scene import/export controls. «Экспортировать пресет» сериализует только текущий `ScenePresetV1`; «Импортировать пресет» принимает JSON этой схемы, требует совпадения scope и применяет только этот preset. Сохранение передаёт ожидаемый scope, выбранный UI, отдельно от JSON envelope, чтобы scoped storage не принимал подменённый `scope`. Существующие полные Composer JSON controls остаются в Общих настройках и явно называются импортом/экспортом всей конфигурации.
- Для проверки персистентности R16 и production требования R38 текущая архитектура: DEV-пресеты сохраняются через file-backed API для Vite/preview; packaged Electron использует localStorage по scope и seed JSON из `scene-presets/index.json`. Изменения текущего Scene Composer в памяти не записываются целиком в localStorage при каждом редактировании; отдельно есть локальный черновик Lily VFX и optional startup `scene-composer.json`. Поведение фиксируется по коду и не расширяется в этой задаче.
- Для R13/R15 русификация применяется только к DOM-меткам и отображаемым текстам, включая видимые Review Notes в DEV-панели. Технические `scope`, `SceneId`, enum и serialized keys остаются прежними; значения enum имеют русские подписи без изменения value.
- Для R36 DEV-компонент остаётся lazy/DEV-only; production-конфиг, defaults и поведение без панели не зависят от его импорта или состояния.

## Корректировка плана после проверки кода

`D01` фиксирует подтверждённую границу: runtime импорт `config.ts` из модели пресета ломает загрузку `vite.config.ts` через `fonts.css` и `.ttf?url`. Схема остаётся единственным источником типов и диапазонов: модель проверяет значения через переданный callback, а browser API/store передают текущий `normalizeConfig`. Схема конфигурации и формат JSON при этом не меняются.

`D02` фиксирует подтверждённую границу существующего API: `save(value)` получает scope только из самого документа, поэтому не способен сверить его с выбранной сценой. UI передаёт ожидаемый scope отдельным аргументом в per-scene API/store; совместимый вызов без аргумента использует документный scope.

`D03` уточняет зону перевода: DEV-панель показывает вложенный Review Notes UI из отдельного компонента, поэтому его пользовательские подписи также принадлежат русификации T03; внутренние статусные enum и API остаются неизменными.

## Обработка ошибок и границы

Пустое имя пресета и неправильный JSON показывают понятную русскую ошибку. Чужой scope, будущая/неподдержанная версия, неправильные типы или диапазоны отклоняются до обновления store. Дополнительные поля безопасно игнорируются после проверки envelope; unknown config keys проходят только через существующую нормализацию. При неполном старом снимке сохраняются текущие пропущенные поля. Не выводить тестовые или временные runtime-state в preset.

Ограничения: не менять художественные defaults, сцены/маршрут, GLB, материалы, свет, облака, фото, анимацию, запись, wrapper или backend; не удалять и не перезаписывать пользовательские preset JSON. Если проверка поведения невозможна только по причине отсутствия браузерной функции, оставить её как ручную приёмку, не заменяя её утверждением о прохождении.

## Вне рамок

- Перерисовка фильма или настройка художественных значений.
- Изменение маршрута, включая возвращение сцены 06 в обычную навигацию.
- Новая система конфигурации/пресетов, persistence backend или серверная синхронизация.
- Автоматическая запись локальных preset-файлов в production-конфигурацию; фактическое назначение localStorage и seed JSON фиксируется по коду.
- Перезапись legacy пользовательских настроек ради обновлённой схемы.
- Создание greeting-параметров/preset scope: в текущей конфигурации greeting не имеет настраиваемых полей; ввод новых таймингов меняет анимационное поведение, которое запрещено менять.
