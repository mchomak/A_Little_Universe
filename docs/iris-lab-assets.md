# Iris Lab: asset contract

From the repository root run `python frontend/scripts/publish-iris-assets.py`. The source is `iris-reconstruction-kit/experiments/run_017_requirements_env`. The script checks the Python export metadata and byte lengths, then copies only `iris_cinematic_rgba.png`, `iris_authentic_rgba.png`, `iris_confidence.png`, and `iris_particles.bin` into `frontend/dev-assets/iris/vasilisa/`, with a generated `manifest.json`. It does not copy the original photograph, annotation, masks or diagnostic reports. This directory is served only by the development server and must not be deployed or exposed publicly without the owner's decision; the derived iris remains personally meaningful.

The manifest contract has `schemaVersion: 1` and identifies `run_017_requirements_env`. PNGs are 1024 × 1024; color images are unpremultiplied sRGB and confidence is linear data. `pupilRatio` is the source ratio of pupil radius to iris radius (approximately 0.1754). The Cartesian PNG has the image top at +Y. Three.js uses its normal texture flip for image upload.

Particles are 80,000 interleaved little-endian float32 records with 28-byte stride: `x, y, z, r_linear, g_linear, b_linear, size`. The coordinate system uses iris outer radius 1, +X right and +Y up; Z is relief in the forward direction. RGB is linear-sRGB. The manifest stores SHA-256 hashes for all four files. The browser loader rejects unknown schema/layouts, mismatched hashes, malformed PNG dimensions and non-finite particles, and disposes allocated textures on failure and on caller request. It does not substitute another iris if loading fails. The reconstruction contains synthetic regions; the confidence map distinguishes them from photographed or corrected regions.
