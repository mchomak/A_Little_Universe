# ADR 0015: Проверка конфигурации без browser-зависимостей в модели пресета

## Контекст

`config.ts` содержит источник схемы, типов и диапазонов, но его runtime-импорт тянет `fonts.css` и font asset с Vite-суффиксом `?url`. Модель пресетов также загружается из `vite.config.ts`, где эти browser/build-зависимости недоступны. Это подтверждённая граница D01.

## Решение

Модель пресетов не импортирует `config.ts` во время выполнения. Она принимает необязательный callback нормализации конфигурации. Browser API/store передаёт существующий `normalizeConfig` при чтении и импорте, чтобы применить известные типы и диапазоны до изменения store. Vite plugin на серверной границе проверяет envelope и scope без загрузки browser assets.

## Почему

Прямой runtime-импорт `config.ts` ломает загрузку конфигурации Vite из-за CSS и `?url`-ресурса. Дублирование схемы в модели пресетов создало бы второй источник типов и диапазонов, который мог бы разойтись с Scene Composer. Переданный callback сохраняет одну схему и оставляет модель исполняемой в Node.

## Последствия

Модель и её проверки могут работать в Node без browser-сборочных загрузчиков. Граница импорта в приложении обязана передавать `normalizeConfig`; серверная проверка ограничена структурой документа и scope. Схема Scene Composer и формат JSON не меняются.
