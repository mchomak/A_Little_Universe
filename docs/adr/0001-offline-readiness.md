# ADR 0001 — Проверяемая готовность текущей сборки без сети

## Контекст

Первый кадр загрузки должен появляться до импорта Three. После подготовки фильм должен переживать потерю сети и перезагрузку страницы, если браузерное хранилище доступно. Регистрация Service Worker не подтверждает наличие всех ресурсов. Основание: спецификация сцен 00–01, §2 и «Самобрифинг».

## Решение

Использовать лёгкий загрузчик с Canvas2D и отложенный импорт FilmCanvas. На production build генерировать версионированный манифест runtime JS, CSS и ассетов и Service Worker на native Cache API, без зависимости Workbox. AssetManager отвечает за подготовку, повторную попытку и результат готовности; кэш относится только к текущей сборке.

Показывать готовность без сети только после проверки полноты и читаемости обязательных ответов из кэша. Прогресс отражает завершённые операции, а не таймер. Служебные запросы, камера и записи не входят в SW-кэш; референсные изображения не становятся runtime-ассетами.

## Почему

Этот подход отделяет быстрый первый кадр от тяжёлого 3D и проверяет именно условие автономного запуска. Одной регистрации SW недостаточно. Для заданного манифеста и жизненного цикла отдельная зависимость Workbox пока не требуется.

## Последствия

Согласованность манифеста, версии кэша и SW становится обязанностью сборки. Ошибки обязательных ресурсов требуют retry; необязательные ошибки не блокируют фильм. При ограничениях хранилища загруженный фильм может продолжиться с явным предупреждением об ограничении offline reload. В dev полная автономность не заявляется; её проверка относится к production build. Сохранность браузерного кэша не гарантируется.
