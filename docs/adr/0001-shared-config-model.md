## Контекст

DEV Composer, сцены и production startup используют художественные параметры; пользовательский JSON может быть частичным или содержать неизвестные значения.

## Решение

Одна версионируемая схема и один store задают активную конфигурацию для Composer и сцен. Defaults неизменяемы; входной JSON нормализуется по известным полям, а отсутствующие и недопустимые значения сохраняют defaults и валидную активную конфигурацию.

## Почему

Отдельные хранилища разошлись бы между live preview, экспортом и production. Полная замена конфигурации не подходит, потому что частичный JSON ожидаем, а пользовательский файл недоверенный.

## Последствия

Новые художественные параметры требуют изменения общей схемы и defaults. Частичные конфигурации используют defaults, а неизвестные поля не становятся частью активной конфигурации.
