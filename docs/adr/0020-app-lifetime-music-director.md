# ADR 0020: MusicDirector на время жизни приложения

## Контекст

Партитура должна продолжаться при переходах между сценами, а плавные переходы требуют одновременно воспроизводить текущий и следующий трек (R14, R36, R40). Существующий AudioDirector владеет лениво создаваемым AudioContext и открывает его в пользовательском жесте. Манифест запрещает отдельный AudioContext для каждой сцены и просит расширять подходящий существующий аудиоменеджер (R12, R13, R15).

## Решение

Сохранить AudioDirector единственным владельцем AudioContext и добавить к нему отдельную музыкальную шину и каналы для media elements. Один MusicDirector управляет музыкой на протяжении жизни приложения. Он владеет ровно двумя повторно используемыми HTML media elements: текущим и подготовленным следующим. Их GainNode подключаются к общей музыкальной шине; музыкальное состояние не создаётся заново для каждой сцены. MediaElementAudioSourceNode для элемента кэшируется и повторно используется.

## Почему

Один владелец AudioContext соответствует существующей системе разблокировки звука и исключает контексты на каждой сцене. App-level MusicDirector позволяет музыке переживать смену сцен, а два потока дают crossfade без создания нового проигрывателя на каждый трек. Декодирование длинных MP3 целиком в AudioBuffer и накопление аудиоэлементов отклонены: спецификация выбирает потоковое воспроизведение через два повторно используемых элемента и ограничивает подготовку одним следующим слотом.

## Последствия

Жизненный цикл музыкальной партитуры отделён от вызова stop для звуковых сигналов. MusicDirector должен координировать единственный активный переход и освобождать ресурсы элементов и музыкальных каналов. Количество media elements остаётся ограниченным двумя даже при долгом просмотре галереи и повторном входе.
