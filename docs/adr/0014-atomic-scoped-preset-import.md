# ADR 0014: Импорт пресета как атомарный патч одного scope

## Контекст

Импортируемый JSON может быть неполным, повреждённым, созданным для другой сцены или содержать старый снимок. Значение `scope` внутри документа не подтверждает, что оператор выбрал именно эту сцену. При этом пресет одной сцены не должен менять корневую конфигурацию, другие сцены или общие настройки. В старых opening-пресетах встречается `openingBackground`, но это общее кадрирование, а не настройка отдельной сцены. Это сохраняет границу, зафиксированную в D02: UI передаёт ожидаемый scope отдельно от envelope.

## Решение

Передавать ожидаемый scope отдельно от JSON на границе API/store, где он берётся из выбранного раздела панели, и сверять его с envelope документа. Сначала полностью разобрать, проверить и мигрировать документ, затем подготовить независимую копию текущего scope и глубоко наложить только разрешённый снимок `scenes.<scope>`. Отсутствующие в старом снимке свойства сохраняют текущие значения. После всех fallible checks применять результат одним вызовом `updateConfig`.

Старое поле `openingBackground` разрешено читать для совместимости, но импорт сцены его не применяет. Кадрирование фона импортируется только отдельным полем Общих настроек.

## Почему

Доверие только `scope` из JSON позволяет документу подменить целевую сцену; отдельный ожидаемый scope связывает применение с выбором оператора. Замена всего корневого объекта может сбросить остальные сцены и общие параметры. Shallow merge теряет вложенные значения, а общие ссылки позволяют случайно менять исходные объекты. Применение до завершения проверок оставляет риск частично обновлённого состояния. Включение `openingBackground` в opening-снимок нарушило бы требование изоляции сцен.

## Последствия

Per-scene API принимает ожидаемый scope отдельно от документа; старый совместимый вызов сохранения без этого аргумента может продолжать использовать scope из envelope, но UI сохраняет с выбранным scope. Импорт сцены изолирован от других сцен, renderer, camera, runtime и общих значений. Legacy opening JSON остаётся читаемым, но его общее кадрирование не переносится импортом сценового пресета.
