# A Little Universe for You


## Iris Visual Lab

The separate development lab uses `run_017`: see [setup and controls](docs/iris-visual-lab.md). Derived assets are served only in development and should not be published.

Приватное интерактивное 3D-поздравление для Василисы. **Реализована последовательность загрузка → настройки → пролог → касание света**, с проверяемым автономным кэшем и необязательной локальной записью реакции. Сцена 04 содержит переход от процедурного источника частиц к имени, ASCII-портрету и первой фотографии. В сцене 02 процедурно формируется и падает семечко с переходом к схематичному началу роста; дальнейший рост лилии и сцены 03, 05–09 остаются техническими placeholders ([контракт и проверка сцены 02](docs/scene-02-seed.md)).

Текущий сценарный источник — [Storyboard v2.0](A_Little_Universe_for_Vasilisa_Storyboard_v2.0.md); [v1.1](A_Little_Universe_for_Vasilisa_Storyboard_v1.1.md) оставлен исходником глав 02–09. Референсы хранятся по [правилам keyframes](references/keyframes/README.md); первая фотография подключена из `images/start_img.jpg`, остальные фотографии и музыка не добавлены.

## Требования

- Node.js **22.12+ в ветке 22** или **24+**, npm (проверено на Node 24.11.1 / npm 11.6.2).
- Современный браузер с **WebGL2** и аппаратным ускорением. WebGPU не требуется.
- Только для необязательного backend: Python **3.12+** и [uv](https://docs.astral.sh/uv/getting-started/installation/). Есть вариант без uv ниже.

## Быстрый запуск — Windows PowerShell

Из корня проекта:

```powershell
cd frontend
npm ci
# Необязательно: название уже имеет значение по умолчанию.
Copy-Item .env.example .env
npm run dev
```

Открыть **http://127.0.0.1:5173**. Не закрывать терминал сервера. Если порт занят, задать другой: `npm run dev -- --port 5174` (Vite использует strictPort).

Дождаться реальной загрузки, выбрать настройки и нажать «Продолжить». Все три согласия исходно выключены; «Продолжить без разрешений» доступно всегда. Камера/микрофон запрашиваются только после выбранных опций и осознанного нажатия. Проверка не записывает. Трекер взгляда ещё не подключён; подготовка камеры не означает, что глаз уже отслеживает взгляд. Отправка автору недоступна, потому что защищённый upload backend не реализован.

Нажать «Открыть подарок»: этот отдельный жест разблокирует AudioContext и запускает запись только при отдельном согласии и успешной проверке камеры/микрофона. Музыкальных файлов пока нет. Пролог длится 18 секунд: один тёплый источник остаётся в центре viewport, две рукописные фразы локально проявляются из штрихов и превращаются в световую пыль. После 16 с появляется инструкция «Прикоснись к свету», после gate — неограниченное ожидание с деликатным дыханием. Касание или keyboard activation запускает мягкий отклик длительностью 0,85 с по умолчанию (настраивается в пределах 0,7–1 с) и непрерывный вход в сцену 02. Выросший бутон тоже ждёт касания. Галерея управляется кнопками, вертикальными свайпами и касаниями; история продолжается с последней карточки. Титры можно остановить или открыть «Читать без движения». В финале доступны повтор, галерея и чтение; повтор не начинает новую запись.

Во время записи видны индикатор и остановка. Фрагменты сохраняются в IndexedDB каждые примерно 4 с (точный интервал зависит от браузера). Финал завершает запись. Панель «Записи на этом устройстве» позволяет скачать или явно удалить сохранённое, в том числе после reload. Браузер может очистить своё хранилище; при закрытии последние фрагменты могут потеряться. Сообщение о запросе скачивания не подтверждает появление файла на диске.

Пауза сохраняет позицию, скрытая вкладка останавливает часы и звук. Уменьшенное движение учитывается системно; качество сцен 02–09 меняется в нижней панели. Reload запускает подготовку заново и сбрасывает согласия, сохраняя доступ к прежним локальным записям. Browser Back не переключает сцены.

DEV Scene Editor открывается кнопкой DEV или по адресу http://127.0.0.1:5173/?debug и доступен только в development. Нижний Timeline раскрывается наведением мыши или нажатием, позволяет переключаться между списком сцен и кадрами активной сцены, ставить фильм на паузу и переходить к доступным позициям. Указано локальное время сцены: общая длительность фильма не фиксирована из-за ожиданий и свободного просмотра галереи. Ожидания касания не имитируются при навигации; шкала отключается в состояниях, где переход недоступен. Загрузка и подготовка доступны отдельно и не имеют общей временной шкалы фильма.

Локальная перемотка доступна для текущих сцен с фиксированной длительностью, кроме перехода после касания в прологе, режима чтения и ожидания касания бутона. Галерея и финал не имеют временной шкалы. Граница ожидания пролога на 18-й секунде показана, но недоступна для прямого перехода: её достигают обычным воспроизведением. Переход к сцене начинает её в предусмотренном начальном состоянии.

Scene Inspector показывает Global и параметры активной сцены; Pin удерживает выбранную панель при переходах, Auto снова следует за сценой. Реальные художественные параметры доступны для 00, 00.1 и 01; для 02–09 дополнительных ползунков пока нет. Доступны пресеты, сброс отдельных изменённых параметров и сцены, импорт и экспорт JSON. Диагностика показывает приблизительную частоту requestAnimationFrame, а не GPU/WebGL FPS. DEV-интерфейс не начинает запись реакции и отсутствует в production, в том числе при `?debug`.

В меню «Просмотр» Timeline доступны скорости 0,25×, 0,5× и 1× с возвратом к предыдущей скорости, а также Loop кадра (`L`) или указанного локального отрезка. Loop доступен в проигрываемом состоянии после интерактивного входа; выход из него оставляет воспроизведение в текущей точке. Наведение на кадр показывает его границы и снимок заметки, если он есть, иначе сообщает об отсутствии превью. В Inspector «История и сравнение A/B» хранит отдельную историю параметров каждой сцены и два временных снимка. Сравнение останавливает фильм в одной точке; после внешнего перехода или перемотки нужно выбрать новую точку. Для загрузки и подготовки сравнение недоступно: у них нет управляемого времени фильма. Импорт JSON и применение пресета очищают историю и A/B.

«+ Заметка» на раскрытом Timeline или `N` во время фильма фиксирует локальное время и состояние и ставит фильм на паузу. В системном диалоге захвата выберите **вкладку с фильмом**, а перед сохранением проверьте превью: браузер не сообщает странице, какую именно вкладку выбрали. Снимок объединяет WebGL и DOM; DEV-панели скрываются на время захвата, поток сразу останавливается. Браузер должен поддерживать захват вкладки и обновлённого видеокадра. Запись реакции и отправка в сеть не включаются. Переходы, загрузка и подготовка не поддерживают создание заметки; некоторые интерактивные состояния нельзя автоматически восстановить по маркеру.

Журнал фильтруется по сцене, кадру и статусу; текст и приоритет редактируются, удаление требует подтверждения. Для экспорта отметьте заметки со статусами `open`, `in_progress` или `ready_for_review`: Markdown сохраняется в корне `dev-reviews/`, его можно скопировать; ZIP содержит Markdown и снимки по тем же относительным путям. Экспорт не меняет статусы; `done` подтверждается вручную. Данные хранятся локально в `dev-reviews/scene-XX/notes.json` и `screenshots/`, каталог исключён из Git. API записи доступен только DEV-серверу с loopback и проверкой Origin; production-сборка его не содержит.

## Scene Editor и production configuration

Defaults и schema v2 находятся в общем config store. Scene Editor доступен только в DEV; настройки production подаются отдельно частичным JSON-файлом по same-origin пути /scene-composer.json. При локальной сборке файл можно разместить в frontend/public/scene-composer.json, чтобы Vite отдавал его из корня сайта. Отсутствующий, некорректный или недоступный optional-файл сохраняет defaults и не блокирует preload; неизвестные поля игнорируются, некорректные значения получают default, неподдерживаемая версия безопасно сбрасывается. Конфигурация v1 мигрируется в v2; новые художественные поля пролога добавлены в schema v2 аддитивно, старые v1/v2-файлы получают их defaults.

Config может содержать global playback speed, quality и DPR; параметры preload/preparation; и настройку пролога. У пролога пять групп: Light, Atmosphere, Typography, Dissolve и Interaction. Яркость ядра, ореола, текста и пыли разделена; настраиваются дыхание, сдержанная глубина пространства, размеры фраз и ритм письма, движение и размер пыли, отклик и тонкая световая волна. Новая вторая фраза — «И решил начать с одной маленькой искры.»; `copyVariant: "legacy"` возвращает прежнюю формулировку. Группа 00.1 включает live-настройки масштаба заголовка, его межстрочного интервала и непрозрачности поверхностей; defaults `1`, `1.08` и `1` сохраняют текущий вид. Устаревшее поле `scenes.prologue.particleReturnFraction` игнорируется. Остальные defaults — Marck Script для пролога, 18-секундный gate, 1 800 частиц в standard quality и локальные шрифты Marck Script, Bad Script, Caveat и Cormorant Garamond. Шрифты входят в сборку и проходят проверку набора глифов, включая Ё/ё. Подробный пример JSON, поля и диапазоны — в [справке Scene Composer](frontend/src/systems/scene-config/README.md).

## Проверки и production build

```powershell
cd frontend
npm run check
npm run preview
```

`check` выполняет ESLint, Vitest и production build со strict TypeScript. Отдельно доступны `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Сборка — `frontend/dist/`; preview — **http://127.0.0.1:4173**. Preview предназначен для локальной проверки статической сборки.

На macOS/Linux frontend запускается теми же `npm ci` / `npm run dev` из `frontend/`.

Для планшета в доверенной локальной сети: `npm run dev -- --host 0.0.0.0`, затем `http://<IP-компьютера>:5173`; при необходимости разрешить доступ в Windows Firewall. Камере и записи нужен HTTPS или localhost: обычный HTTP по локальному IP подходит только для фильма без камеры. Физический планшет/Safari пока не проверены.

Для проверки offline выполнить production build и открыть preview, дождаться проверки кэша, затем отключить сеть и перезагрузить. Готовность подтверждается чтением и проверкой всех обязательных файлов текущей сборки, а не фактом установки Service Worker. При ограничениях storage интерфейс честно разрешает продолжить загруженный фильм без гарантии offline reload. В development полный автономный кэш не заявляется. После обновления сборки старым вкладкам может понадобиться закрытие и повторное открытие.

## Необязательный backend

Backend не нужен для просмотра фильма. В отдельном терминале из корня:

```powershell
cd backend
uv sync --frozen --extra dev
# Необязательно: безопасные значения уже заданы.
Copy-Item .env.example .env
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload --env-file .env
```

Проверка: `Invoke-RestMethod http://127.0.0.1:8000/health` → `{"status":"ok"}`. OpenAPI: **http://127.0.0.1:8000/docs**. Если порт занят, выбрать свободный, например `--port 8001`, и изменить адрес проверки.

Файлы `.env` копировать один раз, сохраняя собственные настройки. Если `.env` не создавался, убрать `--env-file .env`. `VITE_*` — публичные значения; секреты туда не помещать.

На macOS/Linux из `backend/`:

```sh
uv sync --frozen --extra dev
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Backend без uv, Windows, из `backend/`:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
.\.venv\Scripts\python.exe -m pytest
```

На macOS/Linux: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -e '.[dev]'` и `.venv/bin/python -m uvicorn app.main:app --reload`. Точные версии воспроизводит `uv.lock`; pip следует диапазонам `pyproject.toml`. Backend-тесты через uv: `uv run --extra dev pytest`.

## Структура и расширение

```text
frontend/src/
  app/             настройки/проверка/готовность/фильм, координация сервисов, CSS
  bootstrap/       лёгкий Canvas2D preload до импорта Three
  engine/          film state/config/runtime, один Canvas, scene/camera directors
  scenes/          девять сцен и общие схематичные примитивы/анимации
  components/      prompts, галерея, титры, чтение, graphics fallback
  debug/           диагностика только в development
  assets/          место для будущих runtime-ассетов
  shaders/         место для GLSL, импорт через ?raw
  systems/         assets/cache, audio director, media session/IndexedDB
backend/           конфигурация, GET /health, тесты, pyproject.toml, uv.lock
docs/              архитектура, решения, проверки, дальнейшие этапы
references/        арт-референсы вне runtime bundle
```

`engine/filmConfig.ts` задаёт порядок/cues, `film.ts` — gates и переходы, `runtime.ts` — общие GSAP-часы. `SceneDirector` статически импортирует все сцены; каждая использует один постоянный Canvas. Сцены анимируют refs, camera choreography принадлежит `CameraDirector`. Подробные инструкции по добавлению сцен и замене artwork: [архитектура](docs/architecture.md).

## Границы прототипа

Первая фотография и созданный из неё ASCII-портрет подключены в сцене 04 и галерее; остальные фотографии, письмо, музыка, MediaPipe-трекер и защищённая отправка отсутствуют. Backend содержит только `/health`; frontend не отправляет ему видео или camera frames. Отказ optional функций сохраняет фильм. Лилия и сцены 02–03, 05–09 остаются временными материалами.
